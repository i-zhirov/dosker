## Constraints

- **Agent toolchain (settled).** OpenWatcom 2.0 C is the default. It uses
  `wcc` and `wlink`, target `-bt=dos -0 -ml`. Build on Linux x86_64. The
  agent is 16-bit 8086 real mode.
- **OpenWatcom runtime license gate.** The user confirms before Task 1 that
  the OpenWatcom runtime terms permit distributing `DOSKER.EXE` under
  MIT OR Apache-2.0. If the gate fails, the user chooses ia16-gcc. No task
  starts before the gate passes. This is a manual prerequisite, not an open
  question.
- **Agent build script.** `agent/build.sh` sources `$WATCOM/owsetenv.sh` when
  `WATCOM` is set. It fails with a clear message when `wcc` or `wlink` is
  missing.
- **Session boundary.** The version 1 frame header has no session field. The
  serial link is the session boundary. The agent stores `session_id` for
  guest-reboot detection and host bookkeeping. It does not validate
  individual frames against a session ID.
- **Fixture base image.** `agent/fixtures/freedos-base.img` is generated by
  `agent/tools/build-base-image.sh` from `DOSKER_FREEDOS_SOURCE`. It is a
  32 MiB MBR-partitioned FAT16 FreeDOS 1.3 hard disk image with geometry
  128 cylinders, 16 heads, and 32 sectors. Its FAT partition starts at sector
  `2048` (byte `1048576`) and has `63488` sectors. The source image and the
  generated image are not committed. The fixture builder reads the partition
  at `DOSKER_IMAGE_OFFSET`, default `1048576`.
- **Base image source.** `DOSKER_FREEDOS_SOURCE` names a bootable FreeDOS 1.3
  floppy image. The image has `KERNEL.SYS` in its root directory, and its
  `FDISK.EXE`, `SYS.COM`, and `COMMAND.COM` are either in the root or in
  `FREEDOS\BIN`. The FreeDOS 1.3 Floppy Edition source has them in
  `FREEDOS\BIN`.
- **Fixture tooling.** The base image builder uses `qemu-system-i386`,
  `mtools` (`mcopy`, `mdir`, `mformat`), `fdisk`, `sfdisk`, and `timeout`. The fixture
  builder uses `mtools` (`mcopy`, `mmd`, `mdir`, `mtype`, `mformat`). Both set
  `MTOOLS_SKIP_CHECK=1` and `MTOOLS_NO_VFAT=1`.
- **Fixture content.** The fixture contains `C:\DOSKER\DOSKER.EXE`,
  `C:\DOSKER\CONFIG.INI`, `C:\DOSKER\EXITCODE.EXE`, `C:\DOSKER\BIG.TXT`,
  `C:\DOSKER\TWO.TXT`, `C:\APP\`, `C:\AUTOEXEC.BAT`, and `C:\CONFIG.SYS`.
  `BIG.TXT` is 2048 bytes of `X`. `TWO.TXT` is the two lines `ONE` and `TWO`
  with CRLF line endings.
- **QEMU conformance command.**
  `qemu-system-i386 -machine pc -cpu 486 -m 16 -display none -no-reboot -drive file=<image>,format=raw,if=ide,index=0 -serial none -serial unix:<socket>,server=on,wait=off`.
- **QEMU self-check command.** The self-check adds
  `-device isa-debug-exit,iobase=0x501,iosize=0x04` and uses `-serial none`
  for both ports. The agent writes `0` for pass and `1` for fail. QEMU exits
  `1` for pass and `3` for fail.
- **Unix socket path.** The conformance harness uses
  `/tmp/dosker-agent-<pid>-<counter>.sock` to stay under the Unix socket path
  limit.
- **Host codec target.** `dosker-agent-proto` builds on Linux x86_64, macOS
  arm64, and Windows x86_64. It has no platform-specific product dependency.
- **No product image builder, supervisor, or CLI in this slice.** Task 6A
  builds only the test fixture.

**Protocol parity.** The host and agent use these values.

| Item | Value |
| --- | --- |
| Magic | `DKR1` (bytes `44 4B 52 31`) |
| Version | `1` |
| Header | 20 bytes: magic 4, version 1, type 1, flags 1, reserved 1, request_id 4, sequence 4, payload_length 4 |
| CRC | IEEE CRC-32, reflected polynomial `0xEDB88320`, initial `0xFFFFFFFF`, final XOR `0xFFFFFFFF` |
| CRC coverage | Header bytes 0 through 19 and the payload |
| Byte order | Big-endian for every multi-byte integer |
| Flags | `0` |
| Reserved | `0` |
| Max payload | 4096 bytes |
| Frame timeout | 500 ms |
| Retries | 3 after the first attempt, 4 attempts total |
| Max captured output | 1 MiB (`1048576` bytes) |
| Max command line | 127 characters |
| Max PUT or GET file | 16 MiB (`16777216` bytes) |
| Control port | COM2 by default |
| Baud | 115200 by default |
| Serial format | 8 data bits, no parity, 1 stop bit, no hardware flow control |
| Agent version | `1.0.0` |
| HELLO interval | 1 s, for at most 10 s |
| PING interval | 30 s in the supervisor; the host client exposes `ping` |
| Open file handles | One at a time |

**Handshake rules.**

- The agent sends `HELLO` with a new `request_id` every second for at most
  10 seconds.
- The agent that completes the handshake stores `session_id` and answers
  `PING` with `PONG`. It stores the id for guest-reboot detection and host
  bookkeeping. It does not validate individual frames against the id. The
  serial link is the session boundary.
- The agent that has not completed the handshake answers `PING` with
  `HELLO`.
- The host sends `HELLO_ACK` with a six-character lowercase hex
  `session_id`.
- The host rejects `protocol_version` other than `1`.
- A second `HELLO` after the host stores a `session_id` returns
  `ProtoError::GuestRebooted`.

**Retry rules.**

- A frame write waits for an `ACK` with the same `request_id` and `sequence`.
- A `NAK` with the same `request_id` and `sequence` resends the frame.
- A 500 ms timeout resends the frame.
- The fourth failed attempt returns `ProtoError::RetriesExhausted` and closes
  the session.
- A receiver sends `NAK` on a CRC error.
- A receiver that sees four consecutive corrupt frames returns
  `ProtoError::CrcFailed` and closes the session.

**Agent command rules.**

- `EXEC` writes `C:\DOSKER\RUN.BAT` with `@ECHO OFF`, the `SET` lines, the
  `CD` line, and the command redirected to `C:\DOSKER\OUT.TMP`.
- `EXEC` locates the interpreter through `COMSPEC`. It uses
  `C:\COMMAND.COM` when `COMSPEC` is unset.
- `EXEC` reads the child status with `INT 21h/AH=4Dh`.
- `EXEC` streams `OUT.TMP` in 4096-byte `EXEC_DATA` frames.
- `EXEC` stops at `max_output_bytes` and sets `truncated`.
- `EXEC` deletes `RUN.BAT` and `OUT.TMP` after `EXEC_END`.
- `PUT` writes a temporary file in the target directory and renames it on
  success.
- `GET` streams the file in 4096-byte `GET_DATA` frames.
- `STAT` reports `exists`, `size`, `directory`, the four contract attributes,
  and an RFC 3339 timestamp with a `Z` suffix. A directory reports
  `directory` true and `size` 0. A file reports `directory` false. A missing
  path reports `exists` false, `size` 0, `directory` false, all four
  attributes false, and no timestamp. DOS timestamps have no timezone. The
  agent treats them as UTC.
- `SHUTDOWN` closes open files, sends `SHUTDOWN_ACK`, and exits to DOS.
- `/TEST` runs without COM2. It prints `DOSKER SELF-TEST PASS` or
  `DOSKER SELF-TEST FAIL <case>` and writes the same line to
  `C:\DOSKER\TEST.LOG`.

## Risks

- **Generated FreeDOS fixture.** The QEMU CI job needs a bootable FreeDOS
  1.3 floppy image from `DOSKER_FREEDOS_SOURCE`. The source and the generated
  `agent/fixtures/freedos-base.img` are not committed. `build-base-image.sh`
  fails with a clear message when the variable is unset or the file is
  missing. The image is a FreeDOS GPL-2.0 test fixture, not a product base
  image.
- **Base image source tools.** The source floppy must contain `KERNEL.SYS`
  and the `FDISK.EXE`, `SYS.COM`, and `COMMAND.COM` tools in its root or in
  `FREEDOS\BIN`. `SYS C:` writes only the partition boot sector, so the
  builder runs `FDISK /MBR` before `SYS C:`. A source image without these
  tools fails with a clear message before QEMU starts. The FreeDOS 1.3
  Floppy Edition `144m/x86BOOT.img` is the known-good source. The builder
  writes its own minimal target `CONFIG.SYS`; it does not copy the source
  `FDCONFIG.SYS`.
- **Lower baud rates.** The 500 ms frame deadline fits a 4096-byte frame at 115200 baud (~356 ms) but not below about 81920 baud. The agent accepts 9600 to 115200 for handshake and small frames. Full-size transfers require 115200. Scaling the deadline by baud and frame size is a follow-up.
- **Serial throughput.** A 4096-byte frame at 115200 baud takes about 356 ms.
  The 500 ms timeout leaves about 144 ms for the agent ACK. The conformance
  transfer uses 5000 bytes. A 16 MiB transfer at 115200 baud is slow. The
  limit is a protocol bound, not a throughput target.
- **Baud range.** The 16-bit agent supports 9600 to 115200 on a standard
  1.8432 MHz UART. A higher `MACHINE` baud value falls back to 115200. The
  design’s 921600 upper bound applies to hosts with a higher UART clock.
- **Agent data budget.** DGROUP is about 61 KiB of the 64 KiB limit including the 8 KiB stack. Check `agent/build/DOSKER.MAP` before adding static buffers.
- **Agent code size.** The agent links in the large model (`-ml`) with a
  64 KiB code segment. The link fails loudly when the code exceeds the
  segment. The source set is small.
- **Session ID field.** The version 1 frame header has no session field. The
  serial link is the session boundary. The agent stores the `session_id` from
  `HELLO_ACK` only for guest-reboot detection and host bookkeeping. It does
  not validate individual frames against the id. A later protocol version
  needs a session token in the frame or a payload field.
- **`BUSY` during `EXEC`.** The agent runs the child synchronously. The host
  is stop-and-wait and does not send a second `EXEC_REQ` during a command.
  The `BUSY` response is a defensive path. The host client surfaces the code
  when an agent returns it.
- **Directory `STAT`.** `findfirst` sets `_A_SUBDIR` `0x10`. A directory
  reports `directory` true and `size` 0. A file reports `directory` false.
  The four contract attributes are unchanged. There is no directory
  attribute. The host distinguishes a directory from an empty file by the
  top-level `directory` field.
- **Dirty FAT after a kill.** The conformance harness kills QEMU after
  `SHUTDOWN_ACK`. It boots a private copy, so the fixture image stays clean.
  The temporary copy is discarded when the test ends.
- **`/TEST` debug-exit port.** The agent writes port `0x501`. QEMU exits only
  when the `isa-debug-exit` device is present. A normal boot ignores the
  write. The self-check script treats an unexpected QEMU exit code as
  failure.
- **`mtools` partition offset.** The generated base image uses the 1 MiB
  partition offset. The fixture builder reads the partition at
  `DOSKER_IMAGE_OFFSET`, default `1048576`. It runs `mdir` after the copy and
  fails when the DOSKER directory is not visible.


## Deviations

- `exec` and the handshake use deadline-aware sends so a slow ACK cannot extend the caller's timeout.
- `ProtoError::ByteCountMismatch` reports host-detected byte-count mismatches for `EXEC_END`, `PUT_END`, and `GET_END`.
- The agent session closes on send retry exhaustion, matching the contract.
- The agent writes the unsolicited HELLO with `session_write_frame`; `session_send` remains for frames that expect an ACK.
- The handshake accepts a HELLO that arrives while the host waits for a handshake PING ACK, before a session id is stored.
- The base image builder writes the startup batch to both `FDAUTO.BAT` and `AUTOEXEC.BAT`, and uses `fdisk` for MBR geometry because current `sfdisk` rejects `-H`/`-S`.
- The agent serial receiver resynchronizes on the DKR1 magic and uses static frame buffers to stay within the 8 KiB stack.
- PUT retransmissions are idempotent for the last accepted `PUT_DATA`; duplicate `PUT_REQ` frames are ACKed while a transfer is active, and failed requests replay their error.
- The agent primes the DOS free-space query before the handshake to keep the first `PUT_REQ` ACK inside the host timeout.
- EXEC uses `_bios_timeofday` because OpenWatcom does not declare `biostime`, falls back to the `spawnl` return when `INT 21h/AH=4Dh` is 0, and appends `ERR.TMP` after stdout to capture FreeDOS shell errors.
- EXEC validates `workdir` with `path_is_valid` and returns `BAD_PATH` before the ACK. Conformance adds environment, workdir, agent-side `TOO_LONG`, and stateful line-shell tests.
- CI extracts the OpenWatcom self-extracting archive with `unzip` and sets `PATH`/`INCLUDE`, because the installer can fail with a terminfo floating-point exception. CI also adds the `fdisk` package.
